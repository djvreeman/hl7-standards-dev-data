# QA Script for Applied Issues Analysis Report

## Overview

The `qa-applied-issues-report.py` script performs comprehensive validation of the markdown report generated by `applied-issues-analyze.py`. It checks for data consistency, mathematical correctness, logical consistency, and data quality issues.

## Usage

```bash
python scripts/qa-applied-issues-report.py \
    -i data/working/issue-analysis/2025/2025-AllYear/2025-all-resolved-issues-enhanced-v3.csv \
    -r data/working/issue-analysis/2025/2025-AllYear/2025-all-resolved-issues-enhanced-v3_analysis.md \
    -p 2025
```

### Arguments

- `-i, --input`: Path to the input CSV file (same as used to generate the report)
- `-r, --report`: Path to the generated markdown report file
- `-p, --periods`: Analysis periods (same as used to generate report), e.g., `2025` or `2025T1 2025T2 2025T3`
- `--history-json-file`: (Optional) Path to JSON file containing History data if used

## Validation Checks

The QA script performs the following validation checks:

### 1. Performance Band Validation
- Verifies that performance bands (🏎️ Presto, 🚴 Allegro, 🚶 Andante, 🐢 Adagio) match P80 values according to thresholds:
  - Presto: ≤ 60 days
  - Allegro: 61-180 days
  - Andante: 181-365 days
  - Adagio: > 365 days

### 2. Date Logic Validation
- Checks that Applied Date ≥ Created Date
- Checks that Resolution Date ≥ Created Date
- Checks that First Resolved Date ≥ Created Date
- Checks that Resolved to Applied Date ≥ Resolved Change Required Date (warns if not, as this may indicate corrected transitions)

### 3. Category Consistency
- Verifies all issues have a valid category (New, Deciding, Doing, Done)
- Checks that Applied issues are in Doing or Done category
- Identifies issues with "Unknown" category

### 4. Totals Consistency
- Validates that overall summary totals match the actual data
- Checks that period totals match the sum of sub-periods
- Verifies breakdown totals (Realm, Issue Type, etc.) match overall totals

### 5. Status Distribution
- Verifies that status distribution percentages sum to 100%
- Checks for rounding errors

### 6. Breakdown Totals
- Validates that Realm breakdown totals match overall totals
- Validates that Issue Type breakdown totals match overall totals
- Validates that other breakdown totals are consistent

### 7. Negative Values Check
- Identifies issues with negative time calculations (should not occur)
- Notes negative resolution-to-application gaps (may indicate corrected transitions)

### 8. Percentile Consistency
- Verifies that P80 ≥ Median ≥ Min
- Verifies that P80 ≤ Max
- Ensures percentile calculations are logically consistent

### 9. Applied Count Consistency
- Validates that Applied counts in the report match calculated values from data
- Checks consistency across different sections

### 10. Backlog Definition
- Verifies that backlog counts match "Deciding" category counts
- Ensures backlog definition is consistently applied

### 11. Tempo Metrics Consistency
- Validates that resolution time metrics match calculated values
- Validates that application time metrics match calculated values
- Checks that counts match expected values

### 12. Workflow Status Consistency
- Verifies that status values are valid workflow statuses
- Identifies invalid or unexpected status values

### 13. Data Completeness
- Checks for missing required columns
- Identifies issues with missing Created Date
- Reports on Applied Date completeness
- Identifies issues with missing Status

## Output

The script provides three types of feedback:

- **Errors (❌)**: Critical issues that indicate data inconsistencies or calculation errors
- **Warnings (⚠️)**: Potential issues that may be acceptable but should be reviewed
- **Info (ℹ️)**: Informational messages about data characteristics

### Exit Codes

- `0`: QA passed (may have warnings or info messages)
- `1`: QA failed (has errors)

## Integration with CI/CD

The QA script can be integrated into CI/CD pipelines to automatically validate reports:

```bash
#!/bin/bash
python scripts/qa-applied-issues-report.py \
    -i "$INPUT_CSV" \
    -r "$OUTPUT_REPORT" \
    -p "$PERIODS"

if [ $? -ne 0 ]; then
    echo "QA validation failed!"
    exit 1
fi
```

## Troubleshooting

### Common Issues

1. **Import Errors**: Ensure `applied-issues-analyze.py` is in the same directory as the QA script
2. **Missing Columns**: Verify that the CSV file has all required columns (Created Date, etc.)
3. **Period Mismatch**: Ensure the periods specified match those used to generate the report
4. **Date Parsing Errors**: Check that date columns are in a valid format

### Debugging

To debug issues, you can add print statements or modify the validation checks. The script loads and processes data the same way as the main analysis script, so discrepancies indicate issues in either the data or the report generation logic.

## Best Practices

1. **Run QA after every report generation**: Always validate reports before sharing
2. **Review warnings**: Even if QA passes, review warnings for potential data quality issues
3. **Fix errors before proceeding**: Address all errors before using the report
4. **Document known issues**: If certain warnings are expected, document them for future reference
